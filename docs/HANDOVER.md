## 0. 三十秒版本

这个仓库是一个**测试时训练（TTT）快速权重记忆**，加上一套用来问「它到底记得住什么」
的实验。核心代码 373 行，纯 PyTorch，无 Triton、无 CUDA 扩展，笔记本和 8×4090 服务器
上跑同一份代码。15 个测试，其中 1 个在没有 CLIP 权重缓存时跳过。

**目前最重要的三件事，按重要性排序：**

1. **修了 LaCT 官方发布代码里的一个真 bug。** 它的 minimal 实现把正交化后的*梯度*
   赋给了*权重*，销毁先前状态，导致那一层根本无法携带记忆 —— 而且那是默认配置。
2. **最大的效应来自表征，不是更新规则。** 原始 CLIP embedding 有 ~92% 能量共享同一
   个均值方向，所以一张「中性」的空房间图在 key 空间里几乎是每个物体 key 的副本。
   减去均值再归一化，把保持窗口从 ~1 次写入拉到 ~8 次。
3. **「搬家会不会损伤绑定」这个问题，本仓库现有的 fixture 回答不了。** 曾经报出过
   一个方向明确的效应，后来发现它的**符号完全由一个任意的预处理选择决定**，已撤回。
   见第 4 节。

**唯一一条工作纪律**：本文档里每个数字都是实测的。我有五次在没测量的情况下下结论，
**五次都错了**（第 3 节逐条列出）。这个领域里「听起来对」和「是对的」相关性很低。

## 1. 为什么是这个设计

### 为什么和 benchmark 分开两个仓库

`meowbench` 是**模型无关**的评测框架：它把视频交给一个黑盒，然后收回视频再提问。
快速权重层正是它不该包含的那类"被测系统"。两者曾经混在一个仓库里，导致 benchmark
的数据集工作和 TTT 研究出现在彼此的提交历史里，2026-09-08 分离。

**唯一的桥接点**是 `meowbench/adapters/ttt_lact.py`（留在 benchmark 仓库），它
`import ttt_frame.lact`，缺包时报安装指引而不是在首次调用时才炸。要同时开发两边：

```bash
pip install -e path/to/TTT_frame      # 装进同一个 conda 环境
```

两边依赖实测相容：唯一实质交集是 `transformers`，homeSentinel 要 `>=4.49,<5`、
meowbench 要 `>=4.57,<5`，交集 `>=4.57` 满足所有人。**`>=4.57` 是硬下界** ——
`qwen3_vl` 直到 4.57.0 才进 auto mapping，4.56 上加载 Qwen3-VL 会报一个
**看起来像下载损坏**的错。

### 为什么冻结 encoder 而不是微调 VLM

科学理由：encoder 冻结 + 投影固定，那么唯一能把信息从写入带到查询的就只有快速权重
本身。如果绑定活下来了，它就是活在权重空间里。微调过的系统会留下"其实是读出头学会了
任务"这个反驳。

实践理由：CLIP-class encoder fp16 不到 1GB，同一份代码在笔记本上开发、在服务器上跑
正式扫描，迭代按秒计而不是 GPU-小时。

**代价要说清楚**：这测的是**机制**，不是有竞争力的系统。它在 probe suite 上不会赢过
`hf_vlm` 的记笔记 arm，也不打算赢。它回答的是「这个底座到底装不装得下一个绑定」——
这个问题必须先解决，再决定要不要在完整 VLM 上花 GPU-月。

### `lact.py` 的关键 API

```python
mem = LaCTMemory(dim=512, head_dim=64, base_lr=0.05)   # projection="identity" 默认
mem.write(objects, values=owners)   # 定向关联：object[i] -> owner[i]
mem.write(frames)                   # 省略 values 时是自关联（k=v）
guess = mem.read(objects)           # 视频撤销后查询
mem.reset()                         # env_begin 必须调，否则跨环境泄漏
```

两个非显然但 load-bearing 的参数：

- **`values=`**：identity 投影下 k 和 v 否则是同一个向量，记忆只能返回你查询它的东西。
  绑定实验必须用这个参数。
- **`projection="identity"`**（默认）：让记忆留在 encoder 自己的 embedding 空间，
  这样 `read()` 的输出可以直接和 encoder 的其他 embedding 比较。`"random"` 是上游
  的形状，但会把读出投到任意旋转的空间 —— 如果你要和 encoder embedding 比较，
  用 random 会得到无意义的结果（这曾经是一个真 bug，见第 3 节 ②）。

## 3. 我踩过的坑 —— 你不该重踩

按「重新发现它的代价」排序。**前六个属于会伪造结果而不是报错的那一类**，这类最贵。

### 会伪造结果的

**① 上游 LaCT 的 Muon 赋值错误（不是我的 bug，但会毁掉一切）**

`minimal_implementations/bidirectional_lact_layer.py` 写的是：

```python
if use_muon:
    w0 = zeropower_via_newtonschulz5(dw0)   # 赋给了 w0，应该是 dw0
    ...
w0 = w0 + dw0
```

快速权重被正交化后的**梯度**覆盖，先前状态销毁。`use_muon=True` 是默认值。
验证方法（learning rate 设 0，此时更新在数学上必须是恒等变换）：

| | lr=0 是否 no-op | 与 `f_w(q)` 的最大偏差 |
|---|---|---|
| 上游 `use_muon=False` | ✅ | 0.000 |
| 上游 `use_muon=True`（默认） | ❌ | **20.416** |
| 本仓库，两种都对 | ✅ | 0.0003 |

同仓库其他所有实现（causal 层、`lact_ar_video/.../ar_lact_swa_repeat.py`、Triton
kernel）写的都是 `dw0 = zeropower(dw0)`，所以是那个文件独有的笔误。回归测试
`test_zero_lr_is_a_noop`。

> **对本项目尤其致命**：整个实验问的就是"快速权重留不留得住东西"，而上游写法
> **保证答案是「留不住」**，且与科学无关。

**② 读出穿过随机 `W_o`。** 记忆读出的向量被随机矩阵旋转到任意空间，和 CLIP 文本
embedding 根本没法比。三个 arm 报出**逐位相同**的结果。修法：`projection="identity"`。

**③ 选项 E 靠句子长度取胜。** E 的文案是整句 `The information is not available
based on the given context`，A–D 只是人名。实测 CLIP 对**任何**问题（包括"天空是
什么颜色"）都给 E 最高分，14 道题全答 E。修法：打分时减去每个选项与问题无关的
基础亲和度。

**④ 一个格子在「假装随机」。** `0.250 +/- 0.000`，30 个 seed 零方差。看实际输出：
`predictions=[3,3,3,3]` —— 记忆饱和了，四个物体全返回同一个人。4 选 1 蒙对 1 个 =
0.250，**数值上和随机完全一致**，准确率根本区分不出"塌缩"和"瞎猜"。修法：
`run_trial` 同时返回 distinct 预测数，`--full` 标记并单列塌缩格子。

**⑤ SAME/MOVED 一次改了两件事。** "搬家"同时改变填充来源和查询取景，两者**方向相反**。
拆成 2×2 后：filler 主效应 +0.306，query 主效应 −0.256，**交互 +0.513**（比两个主
效应都大）。原来报的"搬家更容易 +0.15"是两者部分抵消的残差。

**⑥ gap 的符号由中心化参考集决定。** 见第 4 节，这是最贵的一课。

### 会浪费时间的

**⑦ 离线时测试卡 331 秒然后 FAILED，而不是跳过。** `except: pytest.skip(...)`
永远等不到 —— `from_pretrained` 每个文件重试 5 次带指数退避，两个文件加起来远超
300 秒的 pytest-timeout。修法：`local_files_only=True`，缺失立刻报错。
实测：空缓存 + 无网从 331 秒 FAILED 变成 34 秒 13 passed 1 skipped。

**⑧ Windows 上 `@torch.compile()` 直接炸。** inductor CPU 后端去调 MSVC，报
`RuntimeError: Compiler: cl is not found`。修法：改成 `MEOW_TTT_COMPILE=1` 才开。
**Linux 服务器上可以开。**

**⑨ 服务器无外网访问 huggingface.co。** `hf-mirror.com` 可用（实测 307）。
`bash scripts/fetch_weights.sh` 会自动探测并验证离线可加载。

**⑩ `git add -A` 两次污染仓库。** 一次把 TTT 代码扫进 benchmark 仓库，一次把调研
目录扫进去。**永远用显式路径 `git add <file>`。** 这也是两个仓库最终分离的直接原因。

### 我在没测量的情况下下结论，然后被打脸的五次

这五次全部指向同一个教训：**这个系统的行为反直觉，不要推理，要测。**

1. 「同屋填充与 key 重叠更多所以覆盖更狠」→ **反了**。broad 均值下 filler_A 0.143
   vs filler_B 0.309，重叠**更多**的伤害**更小**。
2. 「换家把线索本身破坏了这个 confound 已排除」→ **没排除**。我只验证了物体仍以
   自身为最近邻（0.97–0.98），那不足以证明检索不受影响。实测 query 主效应 −0.166。
3. 「线索漂移是恒定代价」→ **不是**。它在 filler B 下**完全免费**（0.975→0.975），
   在 filler A 下**要命**（0.925→0.412）。平均值没有意义。
4. 「填充自相干性是元凶」→ 0.943 vs 0.919，**差异太小**，撑不起 +0.316 的效应。
5. 「旋转量决定损伤」→ **不是**。随机向量填充造成**同样的旋转**（cos 0.857 vs
   0.880）却零损伤。这是整个项目最重要的一个对照，而且是后台分析发现的，不是我。

## 4. 当前真实状态

### 站得住的结论

**(1) 各向异性而非更新规则决定保持窗口 —— 全实验最大、最稳健的效应。**

原始 CLIP embedding 有 ~94% 能量共享同一均值方向（实测 `|mu| = 0.969`，embedding 是
单位范数；`cos(x, mu)` 均值 0.969，`mean(cos²) = 94.0%`）。所以一张「中性」空房间图
在快速权重的 key 空间里 `cos(k_obj, k_filler) = 0.711` —— 几乎是每个物体 key 的副本。
（这个数字我独立复核过：0.7105，与后台分析的 0.7103 一致。参考集不同会让中心化后的
数值不同 —— 我的参考集下降到 −0.53，窄参考集下 −0.017 —— 但两者都远离 0.71，
结论不变。）

**决定性对照**：随机单位向量填充造成**同样的权重旋转**（`cos(W_bind, W_8)` = 0.857
vs 房间图 0.880），却 16 次写入后仍保持 **1.000**，而房间图 2 次就崩到随机。
**旋转量不是机制，key 混叠才是。** 剂量-响应在 key 空间余弦上单调，真实房间图正落
在曲线上（0.710），没有残留的"图像性"。

| 填充写入数 | 0 | 1 | 2 | 4 | 8 | 16 |
|---|---|---|---|---|---|---|
| 原始 CLIP | 1.000 | 0.750 | 0.250 | 0.250 | 0.250 | 0.250 |
| 均值中心化 | 1.000 | 1.000 | 1.000 | 1.000 | 1.000 | 0.750 |

`normalize(x - mu)` 把 `cos(k_obj, k_filler)` 从 0.711 推离 0（我的参考集下到
−0.53，窄参考集下到 −0.017）。**这不是研究贡献，是 CLIP 检索的标准做法**（锥形效应
2203.02053、2405.18570，中心化补救 2112.12777，2022 年就有文献）。

**(2) 损伤只在填充充当 KEY 时发生。**

| 条件 | f=0 | f=1 | f=2 | f=4 | f=8 |
|---|---|---|---|---|---|
| `k=filler, v=filler`（原样） | 1.000 | 0.583 | 0.250 | 0.250 | 0.250 |
| `k=filler, v=zeros` | 1.000 | 1.000 | 1.000 | **1.000** | **1.000** |
| `k=random, v=filler` | 1.000 | 1.000 | 1.000 | 0.958 | 0.958 |

填充作为 value 携带什么是次要的。

**(3) 绑定没被擦除 —— 是读出塌缩了。**

四个返回向量收敛（pairwise cos 0.789 → 0.972），而 `cos(read, 正确人物)` 几乎不动
（0.536 → 0.576）。同一个记忆状态换读出方式：

| 读出方式 | f=2 | f=4 | f=8 | f=16 |
|---|---|---|---|---|
| 原样 | 0.271 | 0.250 | 0.250 | 0.250 |
| 读出减均值 | **1.000** | 0.729 | 0.458 | 0.354 |
| 匈牙利匹配 | **1.000** | **1.000** | 0.750 | 0.604 |

**信息活过了现成读出评为随机的那些写入。**

**(4) Muon 让 `base_lr` 几乎失效。** Newton-Schulz 丢弃更新幅度，所以 `|step|` 在
lr 从 1e-4 到 100 之间**恒定在 ~3.63**；关掉 muon 则 0.03 → 15.5。
**开着 muon 调学习率等于什么都没调** —— 一个 sweep 发现"保持率跨三个数量级平坦"
就是这个原因。已固化为 `test_muon_makes_the_learning_rate_nearly_inert`
（声明为近似不变：bf16 + 5 次有限迭代留 ~2% 残差）。

反方向的意外：`use_muon=False` 时更新小 ~470 倍（`|dW|/|W|` = 0.00057 vs 0.269），
**零填充时就已经是 0.250** —— 什么都没写进去。Muon 是让写入发生的前提。

**(5) 学习率和容量都是平的。** head_dim 16→512、inter_multi 1→4 都不改变保持窗口。
**没有任何超参能买到保持力，只有表征能。**

以上 (1)–(3) 在 RTX 4060 和 RTX 4090 上、以及两个独立实现上都复现。

### 已撤回的结论

**「搬家反而更容易记住」不是效应，是预处理产物。** 中心化需要一个参考集，而问题本身
没有规定用哪个。四个都站得住的选择，各 40 trials：

| 中心化参考集 | filler_A/obj | filler_B/obj | gap@8 | gap@16 |
|---|---|---|---|---|
| narrow（只含实际用到的） | 0.262 | 0.456 | **+0.037** | **−0.038** |
| broad（跨两家 36 物体） | 0.145 | 0.316 | −0.019 | −0.181 |
| home-A only（在线系统唯一算得出的） | 0.529 | 0.157 | −0.062 | −0.281 |
| 不中心化 | 0.861 | 0.850 | 0.000 | 0.000 |

**gap 在参考集之间变号，在 narrow 内部还随 filler 数变号。** 一个独立复分析用 narrow
参考报出 SAME 0.775 vs MOVED 0.631（gap **+0.144**），我们**逐位复现了它的数字**；
换 broad 参考同一份代码给出 SAME 0.944 vs MOVED 0.963。**两边计算都没错，算的是
不同的东西。** 真正驱动结果的是中间两列 —— 中心化改变填充流与存储 key 的重叠度，
保持率跟着重叠度走。home-A 参考下重叠排序翻转，结果也翻转。

**所以：这个 fixture 回答不了搬家是否损伤绑定。** 刺激几何主导一切，"搬家"在这里
和几何不可分离。`scripts/exp_centering_sensitivity.py` 让这一点可复现。

### 可发表性的诚实判断

**「LaCT 2 次写入就崩」不可发表。** 机制是教科书内容（2505.19488 有闭式解：
retrieval = signal + crosstalk，`SNR⁻¹ ~ N/d_k`；2102.11174 在 2021 年就推断出来
并发明 delta rule 来修；2605.05066 证了信息论界），而触发因素是没中心化的 CLIP，
锥形效应和中心化补救从 2022 年就有文献。这么发会犯和 **SR-TTT (2603.06642) 当初
必须撤稿**同一类的错误 —— 那篇 v1 声称的 needle-in-haystack 增益在 v2 被作者自己
撤回，原因是评测 artifact。

另外「快速权重会随流遗忘」已被至少四篇验证过的论文陈述：LongVU-TTT (2608.25729)
原话说它的快速权重"表现为 temporal aggregation state 而非可靠的 long-horizon
episodic memory"、Mem3R (2604.07279)、Elastic TTT (2604.07350)、
Gated DeltaNet (2412.06464)。

**可能有价值的是**：(4) 那条 `base_lr` 在 muon 下失效，据检索没人报过；以及
LaCT 特定的保持窗口量化，LaCT 原文没给。但都需要在真实设定下重做，不能拿这个
synthetic fixture 的数字。

## 5. 下一步（按优先级）

### 优先级 1：两个正交的机制修复

这两个攻击**不同**的一半，可以独立验证：

**(a) 把内层损失从负点积换成 delta/回归形式。** Gated DeltaNet (2412.06464 §3.1)
明确点名负点积是弱的："Linear Attention 和 Mamba2 用简单的负内积损失
`-<S_t k_t, v_t>`，而 Longhorn 用更有表达力的在线回归目标 `||S_t k_t - v_t||²`
来更好地建模 key-value 关联"。

**为什么正好打中我们的机制**：`L = -f_W(k)ᵀv` 无界且无不动点 —— 无论这对已经存得
多好，它都继续把 `f_W(k)` 往 `v` 方向推，所以重复的近重复写入单调地放大一个方向。
这正是实测到的塌缩（read-read 余弦 0.789 → 0.972，`fw0` 首奇异值 1.98 → 3.47）。
回归梯度 `(f_W(k) - v)` **自限** —— 存好了梯度就消失，后续相同写入不再移动状态。
它攻**读出膨胀**那一半，而中心化攻**key 几何**那一半。

**(b) Elastic TTT 的 Fisher 锚定**（2604.07350）：
`θ_{c+1} = θ'_c − λ·F_c ⊙ (θ'_c − θ*_c)`，anchor 是过去快速权重的 EMA。
这是唯一一篇专门针对 LaCT 这个失效模式的已发表方法。后台分析测到它在这里有效
（2 fillers 时 +0.688，配对 t = 32.0）。注意它说 importance estimator 几乎不影响
结果，所以从最便宜的 MAS（`F = EMA(|Δθ|)`）开始。

**先做 (a)** —— 它是机制性修复而不是调参，而且和中心化正交。

### 优先级 2：换一个几何可控的刺激设计

现有 fixture 的刺激几何主导一切，再多 trial 只是把几何巧合测得更精确。诚实的做法是
**直接在 embedding 空间构造受控向量**当刺激（指定与 key 子空间的夹角），这样"场景
变化"和"表征重叠"可以独立扫，才能真正回答最初的问题。

### 优先级 3：接回 benchmark

`meowbench/adapters/ttt_lact.py` 已经是桥接层，`verify-adapter` 过 12/14（两个 FAIL
是 open/numeric 的能力边界 —— 这个 adapter 没有语言模型）。但**先别急着刷分**：
在 probe suite 上它不会赢过记笔记 arm，那不是它的用途。

### 不要做的事

- **不要在现有 fixture 上加 trial 数**来"确认" SAME/MOVED —— 符号由预处理决定，
  加 trial 只会得到更精确的 artifact。
- **不要开着 muon 调 `base_lr`** —— 见 (4)，等于没调。
- **不要用未中心化的 embedding 测任何东西** —— 后台分析的原话是"未中心化 embedding
  上测的一切都应该丢弃，而不是发表"。
- **不要改 `_lact_upstream.py`** —— 它的价值就是保持原封不动可 diff。

## 6. 给接手模型的工作方式建议

1. **先跑一遍再读代码。** `pytest -q` 半分钟出结果，`exp_centering_sensitivity.py`
   直接让你看到那个变号。比读 400 行 README 快。

2. **每个数字都要自己测。** 本项目历史上五次「合理推断」全错（第 3 节）。这个系统
   反直觉：随机噪声填充无害而空房间图致命；与 key 重叠更多反而伤害更小；调学习率
   等于没调。

3. **准确率单独看不可信。** 至少同时看 distinct 预测数（塌缩检测）和
   `cos(k_obj, k_filler)`（几何归因）。`0.250 ± 0.000` 是塌缩的签名，不是随机。

4. **区分「机制坏了」和「表征坏了」。** 本项目最大的两次误判都是把表征问题
   当成机制问题。诊断顺序应该是：先测 embedding 几何（余弦矩阵），再测记忆
   （关联召回 + 置换对照 + 无写入 baseline），最后才测端到端。

5. **临时文件放系统 temp，不放仓库。** 并且 `git add <显式路径>`，永不 `-A`。

6. **服务器和笔记本的差异**：Linux 上开 `MEOW_TTT_COMPILE=1`；服务器无外网，
   先 `bash scripts/fetch_weights.sh`；`pytest` 在 TTT_frame 目录只跑 15 个
   TTT 测试，benchmark 那 329 个要在 meowbench 目录跑。
